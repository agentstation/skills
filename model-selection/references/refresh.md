# Refresh model evidence

Refresh the saved catalog when the user requests current model research or routing changes.
Routine selection uses the saved snapshot.

1. Verify current runtime identifiers against provider documentation and the host catalog.
2. Read the primary benchmark pages and their methodology version.
3. Record unrounded scores, measured task costs, dates, and direct source URLs.
4. Preserve the comparison scope and identify any change to that scope.
5. Update `data/catalog.json` through a reviewable patch.
6. Run the frontier calculation and contract tests.
7. Compare the rendered table with the global table.

Slopalytics republishes AA measurements, so the two sites share benchmark evidence.
API benchmark costs differ from subscription allocation and real task costs.
A small score difference does not establish a practical quality advantage.

Keep owner taste estimates and role preferences separate from measured intelligence.
Retain dated historical evidence when a catalog replaces it.
Policy changes require explicit user authority.
A benchmark refresh does not grant authority to relax role restrictions.
